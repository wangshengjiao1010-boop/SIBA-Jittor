## 3. 新发现的页面细节

### 3.1 创新点不是一次性堆满

创新页至少包含三个稳定状态：

1. 传统空间域→频域→输出；
2. 标出串行处理存在覆盖问题；
3. 加入空间域、频域并行结构。

SIBA PPT 已对创新页的流程框命名并加入逐步出现动画。讲解时应先讲常见注意力，再出现 SIBA 的两路源图查询，不要一开始同时解释全部元素。

### 3.2 代码页的固定样式

- 页面标题在左上角，文件名在右上角。
- 代码放在浅灰色大面板内。
- 单个函数较短时，旁边放完整的小函数、公式或模块结构图，不留无意义空白。
- 单个函数较长时，使用左右两栏连续展示。
- 代码必须出现函数定义和最终 `return`，不能从函数中间截取。
- 重点通过红色鼠标指示，不使用大段解释文字。

### 3.3 现场训练的真实顺序

范例不是只展示已有日志，而是：

1. 在 Jupyter 中加载相同初始权重；
2. 启动真实训练；
3. 显示 Jittor 编译信息；
4. 显示逐步损失；
5. 显示新生成的权重文件；
6. 再切换到模块测试和 W&B 曲线。

SIBA 演示应使用 `bash scripts/demo.sh` 启动短训练，并在终端执行 `screen -r kk` 查看真实损失。短训练只证明代码可运行，最终指标必须引用已经完成的 60 轮训练。

### 3.4 范例没有现场上传 GitHub

视频结尾只打开并展示 GitHub 链接，没有现场输入 token、创建仓库或执行 `git push`。SIBA 视频也不应现场展示密码或 token。仓库应在录制前完成公开上传，视频中只打开 README、日志、结果和迁移记录。

## 5. 范例本身不能照搬的地方

- README 很短，没有完整环境冻结、训练日志、性能日志和逐图指标说明。
- 仓库包含 `__pycache__`、大量数据和运行缓存，版本管理不够整洁。
- `utils/saliency.py` 仍依赖 PyTorch、TorchVision 和 Kornia，并非全部功能都已迁移到 Jittor。
- 部分单元测试使用随机输入和人工容差，只能证明基本接近，不能证明完整训练严格等价。
- 视频对后期训练曲线分化的解释较强，不能作为 SIBA 的表述依据。

因此，SIBA 只模仿它的讲解顺序、代码页结构和演示方式，不复制其不完整的工程做法和过强结论。

## 7. SIBA 需要在 PPT 中保留的代码重点

SIBA 不需要照搬 SFDFusion 的 FFT、IFFT 和 SSIM，因为 SIBA 原算法没有这些模块。SIBA 应展示本项目真实存在的关键迁移代码：

1. `SIBA.__init__` 与完整 `SIBA.execute`；
2. CBSM、SE 和 SE-ResNet；
3. Self-Attention、Cross-Attention 与手动 `normalize`；
4. 数据读取、配对检查和同坐标随机裁剪；
5. Jittor 手动 Laplacian、强度损失和 Sobel 损失；
6. PyTorch 语义的梯度裁剪；
7. PyTorch 兼容 Adam 更新；
8. 训练、推理、数值对齐与完整实验结果。

其中，Laplacian、`normalize`、梯度裁剪和兼容 Adam 是最需要解释的框架差异。它们是为了保持官方数学计算和优化顺序，不是新增算法创新。

复查后已补充两本成对Notebook：`demo/SIBA_PyTorch_逐模块测试.ipynb` 与 `demo/SIBA_Jittor_逐模块测试.ipynb`。PyTorch先导出受控输入、参数、逐层输出、损失、梯度和一步更新；Jittor再按相同顺序显示实际误差。现场短训练也改为先由PyTorch按固定种子导出共享初始权重，再由Jittor加载后训练。

## 8. 诚实结论

- 可以说：官方权重推理迁移高度一致。
- 可以说：Jittor 完成全量 60 轮训练并正常收敛。
- 可以说：前向和损失通过对齐，兼容梯度裁剪与 Adam 在相同参考梯度下通过检查。
- 必须说明：原生 Jittor 梯度相对 L2 误差约 1.05%，一步更新相对 L2 误差约 6.73%。
- 不可说：两框架逐训练步严格相同。
- 不可说：作者未公开的 RoadScene 200 对训练子集与本复现完全相同。
- 不可说：RTX 3090 与论文 TITAN RTX 是同一硬件配置。
