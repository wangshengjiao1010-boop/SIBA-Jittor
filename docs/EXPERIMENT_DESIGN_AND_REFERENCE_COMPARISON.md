## 3. 正式实验设计

### 实验 A：源码完整性

目的：证明不是只迁移主干网络。

- 比较官方与 Jittor 的文件、类、函数和关键超参数。
- 输出 `docs/source_audit_final_20260728.json`。
- 人工审计所有差异块，记录在 `MIGRATION_LOG.md` 和逐文件审计报告中。

### 实验 B：模块与训练步骤对齐

目的：定位框架替换产生的数值误差。

- 同一官方权重、同一输入、同一目标。
- 比较 Res-SE、自注意力、CBSM、交叉注意力、完整输出和三项损失。
- 比较原生梯度、梯度裁剪和一步 Adam 更新。
- 前向和 loss 高度一致；真实梯度相对 L2 约 `1.05%`，一步更新约 `6.73%`。
- 不把“功能可运行”写成“训练步骤严格相等”。

### 实验 C：官方权重端到端迁移

目的：验证 Jittor 推理实现与官方 PyTorch 实现一致。

- PyTorch 与 Jittor 加载同一作者发布权重。
- 测试 MSRS、M3FD、TNO 全部 706 对图像。
- 比较文件名、尺寸、逐像素误差和七项融合指标。
- 这是框架迁移正确性的主要证据。

### 实验 D：完整自训练

目的：证明 Jittor 训练链路不是只支持加载权重。

- 训练数据：MSRS 1,083 对 + RoadScene 200 对。
- 两框架均使用官方 60 轮、batch size 4、patch 128、Adam、StepLR 和梯度裁剪。
- 保存完整日志、420 个官方打印间隔 loss、曲线和最终 checkpoint。
- 自训练结果证明完整训练可收敛，但不能作为严格的逐批次框架排名。

### 实验 E：三数据集量化评测

四个实验分支：

1. 作者权重 + PyTorch；
2. 作者权重 + Jittor；
3. 自训练权重 + PyTorch；
4. 自训练权重 + Jittor。

每个分支在 MSRS、M3FD、TNO 上计算 VIF、SCD、MI、Qabf、SSIM、MS-SSIM、FMI。共 12 个指标组，不删除数据、不减少图像数量。

### 实验 F：性能与资源

- 同一 RTX 3090 上比较同步推理 FPS。
- 单独复现官方未同步计时，用于解释论文 FPS，不与同步结果混用。
- 记录 Jittor/PyTorch 训练总时间和 GPU 最大显存。
- 因论文使用 TITAN RTX，性能表必须标明硬件不同。

### 实验 G：定性结果

- 每个数据集同时展示红外、可见光、PyTorch 融合和 Jittor 融合。
- 官方权重与自训练权重分开呈现。
- 图像来自真实结果目录，不生成替代图，不对图像内容做增强。

## 4. PPT 中实验结果的讲解顺序

1. 先给出源码和模块对齐，说明迁移检查方法。
2. 再给出完整 60 轮损失曲线，证明训练链路完整。
3. 展示官方权重的 706 张输出对齐，这是最严格结果。
4. 展示三数据集官方权重指标，并与论文 Table 1 对比。
5. 单独展示完整自训练指标，明确它验证可训练性，不是严格配对排名。
6. 展示同步速度、训练时间和显存。
7. 展示定性融合图和已知限制。

## 5. 仍需避免的错误表述

- 不写“与原论文一模一样”；作者未公开 RoadScene 200 对名单。
- 不写“PyTorch 与 Jittor 60 轮逐批次对齐”；shuffle、裁剪和初始化轨迹不同。
- 不把 20 步现场训练作为最终实验。
- 不把官方权重指标写成自训练指标。
- 不把 M3FD 半分辨率写成缩水实验；这是论文 Section 4.1 对全部 300 对图像规定的协议。
- 不把 RTX 3090 的速度写成 TITAN RTX 的同硬件复现。
