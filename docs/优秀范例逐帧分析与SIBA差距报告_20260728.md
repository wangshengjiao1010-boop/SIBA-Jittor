## 3. 视觉规范

### 3.1 字体

- 页面大标题最接近本机 `Noto Sans SC Bold`，不是常规微软雅黑。
- 普通中文使用 `Noto Sans SC`。
- 代码使用 `Cascadia Code`，中文注释由中文字体回退显示。
- 代码页最低字号按 18 pt 设计；大标题约 30–36 pt，封面标题更大。

### 3.2 版式

- 背景为暖白色，接近 `#F6F1EE`。
- 标题固定在左上，粗黑，无标题文本框边框。
- 页脚为浅灰小字：左侧主题，中间项目名，右侧页码。
- 内容区使用大面积浅灰圆角底板，接近 `#ECECEC`。
- 代码页采用左右两列；右侧不得留空，可放完整第二个函数、公式、模块图或结果图。
- 每页只讲一个模块或一个完整逻辑单元。

### 3.3 色彩

- 浅橙：主处理模块。
- 浅粉：输入、输出或模态标签。
- 浅紫：问题、结论或损失。
- 浅蓝/浅绿：中间特征和支路。
- 箭头为中性灰色，线条较粗。
- 代码关键字为蓝色，解释性注释为绿色，关键说明为红色。

### 3.4 动画

- 动画只用于按逻辑逐步出现，不使用复杂转场。
- 创新点页按“原流程→问题→新流程”逐步展示。
- 架构页按“输入→模块→中间特征→输出”逐步展示。
- 代码页主要用红色激光点指示，不依赖大量动画。

## 4. 优秀项目在迁移之外做了什么

1. 建立 `ptTest.ipynb` 与 `jtTest.ipynb` 两套隔离 Notebook。
2. 为图像读写、指标、损失、数据集、模型模块、训练步和推理编写对应测试。
3. 从 PyTorch 导出初始权重，再加载到 Jittor，减少初始化差异。
4. 记录 W&B 训练曲线并在浏览器展示。
5. 保存训练权重、推理结果、测试数据和部分 RoadScene 数据。
6. 现场执行训练和推理，打开新生成结果图。
7. PPT 用完整函数或类讲迁移，不只展示框架图。

## 5. 优秀项目本身存在的限制

优秀范例可学习的是展示方法，不应照搬其不严谨结论。

- `README.md` 很短，没有完整环境冻结、训练 Log、性能 Log 和逐图指标说明。
- `utils/saliency.py` 仍直接依赖 PyTorch、TorchVision 和 Kornia，并标注“未使用”，不能视为完整 Jittor 迁移。
- Notebook 的平均频域损失为 PyTorch `1.197665`、Jittor `1.330184`，差异明显，但视频仍使用“完整正确对齐”的强结论。
- 多处单元测试使用随机输入和人工容差，测试通过不等于完整训练严格等价。
- 训练曲线后期分叉，且讲解中提出“为 Jittor 重新调参”，这会偏离只迁移框架、不改原算法的任务约束。
- GitHub 末页只展示链接；视频中没有现场创建仓库或上传文件。
