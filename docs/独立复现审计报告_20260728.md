## 3. 主要发现

### [已整改] F-01：历史原始报告的 `passed: true` 漏检真实参数更新误差

`logs/alignment/jittor_gpu_report.json` 的受控测试结果为：

| 项目 | 结果 |
|---|---:|
| 激活最大绝对误差 | `2.0206e-4` |
| loss 最大绝对误差 | `2.9802e-6` |
| 真实反向梯度余弦相似度 | `0.9999452542` |
| 真实反向梯度相对 L2 误差 | `0.0105084`，约 `1.05%` |
| 裁剪后真实梯度相对 L2 误差 | `0.0104638`，约 `1.05%` |
| 真实一步参数更新余弦相似度 | `0.9977375768` |
| **真实一步参数更新相对 L2 误差** | **`0.0672686`，约 `6.73%`** |
| 真实一步参数更新最大绝对误差 | `1.9882e-4` |

生成该历史原始报告时使用的旧版通过条件只检查：

1. 手工前向与模型前向是否一致；
2. 激活和 loss 是否在阈值内；
3. 真实梯度余弦是否大于 `0.999`；
4. 把 **PyTorch 参考梯度** 注入 Jittor 后，裁剪和 Adam 是否对齐。

它没有检查：

- `gradient_preclip.relative_l2`；
- `gradient_postclip.relative_l2`；
- `parameter_update.relative_l2`；
- `parameter_update.max_abs`。

因此，历史 `passed: true` 只能证明：前向和损失接近，且自定义裁剪/Adam 在输入相同参考梯度时实现正确。它不能证明 Jittor 自动微分生成的完整训练步骤与 PyTorch 严格等价。

这不是数据造假。当前 `tools/check_jittor_alignment.py` 已将真实梯度相对 L2、真实参数更新余弦和相对 L2 纳入判断，并单独输出 `strict_training_equivalence_passed: false`。历史原始 JSON 保留不改，修正后的分层结论保存在 `logs/alignment/alignment_assessment_20260728.json`。

### [高] F-03：不能宣称“与原论文一模一样”

存在以下不可消除或尚未消除的差异：

1. 论文只说明从 RoadScene 随机选择 200 对，没有公开文件名和随机种子。当前项目使用 seed `2025` 从 221 对中确定 200 对，过程可复现，但无法证明与作者子集相同。
2. 论文写“训练输入由 RGB 转换为 Y、Cb、Cr”，官方 `train_loader.py` 实际对红外和可见光都使用 OpenCV 灰度读取。迁移遵循的是官方代码，不是论文文字。
3. 论文硬件是 NVIDIA TITAN RTX 和 Intel Core i9-9900K；本项目实测硬件是 RTX 3090，CPU 也不同。
4. 作者没有发布训练时每轮的样本顺序、随机裁剪坐标、初始化状态和完整训练日志。

因此可核验的最强结论是：**忠实迁移公开官方代码，并在公开测试协议下复现作者发布权重的结果。**

### [中高] F-05：两框架 60 epoch 自训练不是严格受控对齐实验

Jittor 和 PyTorch 均完成 60 epoch，但完整训练并未做到以下条件完全相同：

- 两框架没有从同一份随机初始化参数开始；相同 seed 不保证 PyTorch 与 Jittor 使用相同初始化随机序列和算子实现。
- PyTorch DataLoader 与 Jittor Dataset 的 shuffle 实现不同，batch 顺序不能按 seed 自动一一对应。
- 随机裁剪使用 NumPy，但裁剪调用顺序会随 batch 顺序变化。
- 不同框架 CUDA 算子和自动微分存在数值差异。

所以自训练最终结果差异不能单独证明“迁移错误”，也不能证明“严格等价”。它只能证明两个训练实现都能够在完整数据上运行并收敛。

部分自训练指标差异：

| 数据集/指标 | PyTorch | Jittor |
|---|---:|---:|
| MSRS MI | `5.0431` | `5.4605` |
| M3FD_2x MI | `3.5466` | `3.8643` |
| TNO MI | `3.1625` | `3.3344` |
| M3FD_2x Qabf | `0.6491` | `0.6296` |

严格训练对齐应从同一初始化 checkpoint、同一显式 batch/crop 清单开始，并比较多批次的逐层梯度和参数更新。

### [中] F-06：SSIM 协议采用论文数值一致的 MEF-SSIM，不是链接工具的默认活动分支

项目发现，链接评测仓库当前活动的 pairwise SSIM 调用不能复现论文 TNO 的 `0.932`，因此使用同一工具中保留的 `mef_ssim` 实现。独立数学验证结果为：

| 指标 | 快速实现与原实现绝对误差 |
|---|---:|
| MEF-SSIM | `1.22e-15` |
| MS-SSIM | `2.22e-16` |
| FMI | `0` |

该选择已记录且数值实现等价，不属于隐蔽造假；但报告和 PPT 必须写明“采用与论文 Table 1 数值一致的 MEF-SSIM 解释”，不能写成“完全采用评测仓库默认活动代码”。

### [中] F-07：MATLAB 日志存在退出环境错误，指标计算本身成功

12 组 MATLAB 日志均出现：

`函数或变量 'Settings' 无法识别。`

该错误发生在 MATLAB `exit` 阶段；每次进程返回码为 0，逐图 CSV 和汇总 CSV 均已生成，独立重跑也出现相同退出错误。当前证据支持“指标计算成功、退出环境异常”。

`tools/run_matlab_evaluation.py` 只检查进程 return code，不扫描日志中的错误文字，鲁棒性不足。后续应同时检查：return code、输出 CSV 存在性、行数、有限值和日志错误关键词。

### [中] F-08：`complete: true` 是产物完整性结论，不是反造假结论

`tools/validate_experiment.py` 主要检查：

- 训练日志是否存在 420 条匹配行以及 0–59 epoch；
- checkpoint 是否只有一个且大于 1 MB；
- 图片数量是否正确；
- `summary.json` 自报数量是否正确；
- 指标 CSV 文件是否存在且行数正确；
- marker 文件是否存在。

它不检查：

- 训练日志与 checkpoint 的密码学绑定；
- checkpoint 是否由该日志对应训练产生；
- 全部输出 PNG 的哈希；
- 输出是否为输入图直接复制、常量图或重复图；
- 指标是否从融合图重新计算；
- marker 是否只是人工创建的空文件；
- 日志和 CSV 是否在生成后被修改。

因此 `complete: true` 只能解释为“预期文件和数量齐全”。本次独立审计另外补做了图片、CSV、checkpoint 和数据哈希核验，但仍不能替代不可变证据链。

### [中低] F-09：性能结果不能直接与论文 TITAN RTX FPS 对比

论文在 TITAN RTX 上按未同步 CUDA 计时报告 FPS；本项目在 RTX 3090 上同时记录：

- 官方未同步计时；

RTX 3090 同步结果为：

| 框架 | MSRS FPS | M3FD_2x FPS | TNO FPS |

### 7.2 逐文件语义结论

#### `args/args_SIBA.py`

- 默认 epoch `60`、batch `4`、patch `128`、学习率 `1e-4`、StepLR `25/0.5`、weight decay `0` 均未改变。
- 文件中字面上重复定义 `patch_size`，官方和 Jittor 均保留，没有擅自清理。

#### `base_blocks/cbsm.py`

- CBSM 的实际结构是：`Conv3×3 → PReLU → Conv3×3 → SE → PReLU`。
- 没有 BatchNorm，也不是 SiLU。
- 迁移仅替换 `torch.nn` 为 `jittor.nn`，并将 `forward` 改为 Jittor 的 `execute`。

#### `base_blocks/SE.py`

- 保留全局平均池化、两层无偏置 Linear、ReLU、Sigmoid 和逐通道缩放。
- `inplace=True` 被去除是 Jittor API 差异，不改变函数输出。

#### `base_blocks/se_resnet.py`

- 保留残差投影、两层卷积、PReLU、可选 SE 和残差相加顺序。
- 未改变通道、卷积核、步长、padding 或 `use_res/use_se` 行为。

#### `base_blocks/restormer.py`

- 8 个官方类全部保留，无类或方法缺失。
- `F.normalize` 被显式实现为 `x / max(||x||, eps)`，与 PyTorch 公式一致。
- `nn.Parameter(torch.ones/zeros)` 改为公共 `jt.Var`；检查点中相应变量均被注册，137 个状态键完整。
- Self-Attention、Cross-Attention 的 q/k/v 生成、rearrange、归一化、矩阵乘、softmax、投影和残差顺序均保留。
- GELU 使用 Jittor 精确 erf 实现，与当前 PyTorch 默认精确 GELU 一致。
- 前向误差很小；真实反向误差仍需定位，重点可能涉及 normalize、LayerNorm、softmax 和框架卷积反向。

#### `loader/train_loader.py`

- 文件排序、红外/可见文件名断言、灰度读取、除以 255、CHW 排列和同坐标随机裁剪均保留。
- `kornia.utils.image_to_tensor` 替换为 `np.expand_dims(...).astype(np.float32)`，输出形状与数值等价。
- Jittor 必须设置 `total_len`；这是 Dataset API 适配。
- 两框架 shuffle 顺序不保证一致，是完整训练不可逐 batch 比较的原因之一。

#### `loader/test_loader.py`

- 保留可见图 RGB 读取、Y/Cb/Cr 分解、红外灰度读取、文件名和原尺寸返回。
- `transform.ToTensor` 与官方 TorchVision `ToTensor` 均输出 `[0,1]` CHW。
- 增加 `set_attrs(total_len=...)` 是 Jittor Dataset 必需适配。

#### `loss/loss.py`

- 总损失仍为 `10×Laplacian + 0.1×Intensity + Sobel`。
- Sobel kernel、最大梯度选择和 L1 计算未改变。
- Kornia Laplacian 被显式实现为归一化 3×3 Laplacian、reflect padding 和分组卷积。
- 前向 loss 最大误差 `2.98e-6`；反向误差尚未完全定位。

#### `models/SIBA.py`

- `in=1`、`mid=48`、`out=1`、SA 深度 1、CA 深度 1 保持。
- 红外/可见浅层分支、两路 Self-Attention、四个 CBSM、四路 Cross-Attention、四路拼接、两级融合和输出模块全部保留。
- 官方 checkpoint 137 个键、565,941 参数与 Jittor 模型完全对应。
- 未发现删层、减通道、绕过 attention 或只保留推理分支。

#### `train.py`

- 训练循环、loss 权重、epoch、batch、StepLR、clip `0.01` 和最终保存逻辑保留。
- 官方 PyTorch Adam 被 `compat/pytorch_adam.py` 替代，原因是 Jittor 内置 Adam 的 epsilon 放置方式与 PyTorch 1.10 不同。
- 给定相同 PyTorch 参考梯度时，裁剪最大误差 `4.89e-9`，Adam 更新后参数最大误差 `2.98e-8`。
- 这只证明兼容实现公式正确，不证明上游 Jittor 自动微分梯度完全相同。

#### `test.py`

- 模型加载、逐图推理、Y/Cb/Cr 合成、clamp 和保存均保留。
- Jittor `ToPILImage` 要求 HWC，因此增加 `transpose(1,2,0)`；官方权重端到端输出验证支持该适配正确。
- 原始未同步计时被保留；项目另用工具记录同步计时。

#### `utils/RGB2YCrBb.py`

- RGB↔YCrCb 变换系数、通道顺序、bias 和 clamp 均保留。
- 增加 NumPy clamp 分支只服务于辅助工具，不改变 Jittor 推理路径。

#### `utils/resize_resolution.py`

- 与官方字节一致；M3FD 使用宽高整除 2 和 Pillow LANCZOS。

#### 兼容文件

- `compat/pytorch_adam.py`：保存一阶矩、二阶矩和偏置校正，按 PyTorch Adam 公式更新。
- `compat/pytorch_clip.py`：计算全参数梯度全局 L2 norm，并按 PyTorch `clip_grad_norm_` 的 `1e-6` 规则缩放。
